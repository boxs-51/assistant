## 3. Current generated-content facts

### Shared provider execution boundary

```text

    -> jsonable(...)
    -> InferenceResponse.message.content
```

Thus a provider-neutral post-response canonicalization boundary in the shared chat handler can serve both DIRECT and AGENT consumers without embedding CAS persistence into provider-specific converters.

## 4. Generated source classes

F7 distinguishes four authorities even when all converge to the same canonical FileAsset model:

1. **provider-response generated media**
   - source material arrives after provider decoding;
   - initiation authority is the authenticated provider request/execution context;
   - provider payload fields do not grant CAS ownership.

2. **COMMITTED tool-result generated media**
   - source material originates from an Agent tool result;
   - durable `AgentToolResult.commit_state == "COMMITTED"` is a mandatory precondition;
   - PROVISIONAL/ambiguous results cannot create durable/model-visible asset references.

3. **ordinary F6 user-upload assets**
   - already canonical before provider execution;
   - NOT re-ingested by F7.

4. **F5 provider-hydrated request assets**
   - transient provider projection of an existing canonical asset;
   - provider file identity remains execution transport only;
   - NOT re-ingested by F7.

These authorities MUST NOT be conflated merely because they share attachment/media schemas.

## 5. Canonical identity and owner authority

A durable generated object that is admitted by F7 must end as:

```text

AssetDescriptor.asset_id = <canonical id>
GatewayAttachment.asset_id = <canonical id>
GatewayAttachment.source = "asset"
GatewayAttachment.uri = asset://<asset_id>
```

Canonical generated attachment state MUST NOT also retain the same object's:
- inline base64 payload;
- raw bytes;
- provider file ID;
- provider URI;
- object-store key;
- signed URL;
- temporary local path;
- browser object URL.

Owner authority is derived from the already-authenticated request/execution context.

No provider field, tool output field, URL, provider file ID, filename, metadata scalar or client-supplied user field may mint or override `owner_user_id`.

If authenticated owner authority is unavailable at the canonicalization point, F7 fails closed and MUST NOT create an asset.

## 6. Provider-response canonicalization composition point

The future production boundary is frozen as:

```text
provider converter
    -> decoded GatewayResponse / GatewayMessage
    -> ChatExecutionHandler shared post-response canonicalization hook
    -> canonical GatewayResponse
       containing only asset identity for durable generated binary/media
    -> DIRECT return
    -> ProviderInferenceAdapter -> AGENT InferenceResponse
```

For non-stream responses, the hook point is **after**
`ProviderExecutor.execute(...)` returns a fully decoded `GatewayResponse`
and **before** `ChatExecutionHandler.execute_with_fallback(...)` returns that response.

This keeps:
- provider converters as provider decoding/lowering owners;
- provider routing/fallback/deadline/model selection unchanged;
- DIRECT and AGENT on one provider-neutral canonicalization boundary.

F7 production MUST NOT persist CAS assets inside Gemini/OpenAI/Ollama-specific converters.

## 7. Streaming boundary

Current `ChatExecutionHandler.stream_with_fallback(...)` yields provider chunks as they arrive.

F7 MUST NOT create a durable asset from an incomplete chunk or partially assembled generated object.

Streaming invariants:

```text
partial chunk
!= terminal generated object
!= durable FileAsset authority
```

A streaming generated object may be canonicalized only after a provider-neutral terminal assembler proves all of:
- object completion;
- deterministic object boundary/identity for that response;
- complete bounded bytes are available;
- MIME is known or safely defaults to application/octet-stream;
- authenticated owner authority is still valid;
- cancellation has not invalidated the terminal object.

If those conditions are unavailable, generated binary/media streaming MUST fail closed for canonical asset creation. Text/tool-call streaming may continue under existing provider semantics.

No partially assembled FileAsset may become READY or model/history visible.

Cancellation or provider error before terminal completion creates no durable visible asset reference.

## 9. CAS ingestion authority and exactly-once boundary

F7 generated-content canonicalization must call the canonical CAS application service.

Preferred future application composition:

```text
GeneratedAssetCanonicalizer
    -> validate authenticated owner + completed bounded source object
    -> decode/resolve source transport into bounded byte stream
    -> AssetService.ingest_stream(
         owner_user_id=<authenticated authority>,
         filename=<metadata only>,
         mime_type=<metadata>,
         stream=<bounded complete bytes>,
         max_bytes=<F7 generated-content bound>,
         origin_type=<generated-source class>,
         origin_id=<stable source object identity when available>,
         metadata=<non-authoritative provenance>
       )
    -> READY AssetDescriptor
    -> canonical GatewayAttachment
```

`AssetService.ingest_stream` is the storage/finalize authority. Generated canonicalization must not duplicate its SQL/ObjectStorage transaction protocol.

The orchestration layer owns **exactly-once canonicalization per completed generated source object**.

Because current `AssetService.ingest_stream` generates new asset/blob IDs and does not itself prove content-level deduplication, F7 production MUST NOT assume repeated calls are automatically idempotent.

A later production CLAIM must freeze one of:
- a stable source-object key / execution-scoped memo ensuring the canonicalizer invokes ingest exactly once; or
- an explicitly audited idempotency/dedup primitive.

Retry after an ambiguous successful ingest MUST fail closed unless the orchestration layer can prove the already-created canonical result.

Content hash is storage integrity evidence, not by itself ownership or replay authorization.

## 10. Generated bytes and URL/provider transport

For provider `inlineData` or equivalent complete bounded bytes:
- transport base64 may be decoded only as transient source material;
- bytes are ingested to CAS;
- returned canonical message content replaces transient binary identity with `asset_id/source="asset"/asset://...`.

For provider `fileData`, URL or provider remote handle:
- URI/provider identity remains transient source transport only;
- F7 may canonicalize only if an authenticated provider-neutral resolver can obtain complete bounded bytes under the same request authority;
- a URL string alone is not durable CAS evidence;
- if complete bounded content cannot be resolved safely, canonicalization fails closed rather than persisting the URL as canonical history identity.

Provider remote cleanup/delete authority remains CLOSED.

## 11. Durable message/history boundary

Once a generated object is canonicalized, any durable/model-visible message representation must carry only canonical asset identity plus non-authoritative display metadata.

No durable state may persist both canonical `asset_id` and the original base64/provider transport identity for the same generated object.

The canonicalization hook must execute before a generated object is accepted into durable/history state.

Session regeneration remains CLOSED in F7-0. If a later implementation proves regeneration code must change, production work stops for fresh authority.

## 12. Failure semantics

F7 fails closed on:
- missing authenticated owner;
- incomplete/ambiguous generated object;
- invalid base64/byte transport;
- generated content exceeding the frozen size bound;
- provider URL/handle that cannot be resolved to complete bounded bytes;
- AssetService ingest/storage/finalize failure;
- cancellation before terminal canonicalization;
- ambiguous ingest replay without proven canonical result;
- tool result not durably COMMITTED.

Failure MUST NOT:
- expose a durable provider/base64 identity as substitute canonical state;
- fall back to legacy `/v1/files`;
- create partial READY FileAsset state;
- mutate provider routing/fallback policy;
- infer deletion/cleanup/GC authority.
