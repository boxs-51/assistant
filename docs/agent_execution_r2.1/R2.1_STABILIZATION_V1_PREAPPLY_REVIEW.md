## 1. Executive decision

**Decision: DO NOT APPLY v1 AS-IS.**

The patch is directionally correct and addresses the original `MappingProxyType` durable JSON failure. The serializer and DurableAgentStore integration are sound in principle, strict WAITING behavior is correct, and the provider `retryable` class attributes do not change the current provider RetryPolicy because that policy already retries by exception type.

However, v1 does not yet satisfy its own R2.1 exit gate in two important areas:

```text
P0-A  structured failure metadata is lost at chat transport surfaces
P0-B  the failure-domain regression test does not reproduce a real
      "provider succeeds -> persistence fails" path
```

There are also several P1 coverage/completeness issues.

Recommended action:

```text
revise to R2.1_stabilization_v2.patch
then run:
    git apply --check
    focused R2.1 tests
    architecture suite
    streaming/non-streaming transport regressions
```

## 2. Hunk 1 — `se/src/runtimes/agent/serialization.py`

### Verdict: PASS

The new serializer correctly establishes a fail-closed durable JSON boundary.

Good decisions:

```text
Mapping/MappingProxyType -> recursive dict
tuple/list -> JSON list
set/frozenset -> deterministic list
Enum -> value
datetime/date -> ISO string
UUID -> string
BaseModel -> recursive Python dump
NaN/+Inf/-Inf -> rejected
unknown objects -> explicit serialization error
non-string mapping keys -> rejected
```

The non-string-key rejection is preferable to `str(key)` because stringification can collapse distinct keys.

The deterministic set sort is adequate for persistence reproducibility.

### No blocking issue found

The serializer intentionally does not support arbitrary bytes/custom classes/Decimal unless explicitly added later. Fail-closed behavior is consistent with R2.1.

## 3. Hunk 2 — `se/src/runtimes/agent/persistence.py`

### Verdict: PASS WITH P1 FOLLOW-UPS

The patch normalizes all principal Agent aggregate JSON surfaces before repository writes:

```text
AgentExecution:
    request
    result
    context_state
    transcript
    inference_request
    inference_response

AgentTask:
    wait_reasons
    input
    output

AgentMessage:
    payload

AgentIteration:
    tool_call_ids
    transcript
    inference_request
    inference_response

AgentToolCall:
    arguments
    extra_metadata

AgentToolResult:
    output
    extra_metadata
```

Production audit confirms the normal production Agent persistence writes flow through `DurableAgentStore`, so placing semantic normalization here is consistent with the agreed architecture.

### Legacy continuation merge

`update_checkpoint()` preserves an already-observed `context_state["continuation"]` member during the sequential read/merge/write path. This matches the corrected narrow R2.1 guarantee.

It does **not** solve concurrent dual-writer races, and the contract should not claim that it does. R7 owns that elimination.

### P1-01 — dormant `update_tool_call` repository defect remains

Current repository code has an existing mismatch:

```text
AgentRepository.update_tool_call(tool_call_id, values)
    -> self.get_tool_call(tool_call_id)

AgentRepository.get_tool_call(execution_id, tool_call_id)
```

There are currently no production callers of `update_tool_call()`, so this does not make v1 fail at runtime today. But the R2.1 patch touches/claims normalization for this path without proving it is callable.

Recommendation:

```text
either
    fix this defect in a separately reviewed stabilization hunk
or
    explicitly leave it outside R2.1 exit coverage and file a P1 follow-up
```

Do not silently broaden this patch without a regression test because `tool_call_id` is unique only together with `execution_id`.

### P1-02 — coverage is concentrated on AgentExecution JSON

The implementation protects many JSON surfaces, but v1 tests only prove the real SQL path primarily for AgentExecution checkpoint fields.

Add focused DurableAgentStore tests for at least:

```text
AgentTask.output
AgentMessage.payload
AgentToolCall.arguments/extra_metadata
AgentToolResult.output/extra_metadata
```

with nested immutable data.

## 6. Hunk 5 — `se/src/provider/exceptions.py`

### Verdict: PASS

The patch adds:

```text
ProviderError.failure_domain = PROVIDER
ProviderError.retryable = False
ProviderRateLimitError.retryable = True
ProviderUnavailableError.retryable = True
```

Call-site audit confirms current `RetryPolicy` already decides retryability using:

```text
isinstance(error, ProviderRateLimitError)
isinstance(error, ProviderUnavailableError)
```

Therefore these class attributes do **not** introduce a new retry loop or alter current provider retry behavior. They align error metadata with behavior that already exists.

`NoAvailableProviderError` remains terminal/non-retryable at the outer Agent result boundary, which is appropriate after provider routing/fallback has been exhausted.

### Verdict: PASS WITH P1 EVENT GAP

This is not a lifecycle blocker, but it is needed for consistent observability and the stated R2.1 failure-domain contract.

## 8. Hunk 7 — `se/src/runtimes/workflow/runtime.py`

### Verdict: BLOCKED — P0 TRANSPORT CONTRACT INCOMPLETE

The WorkflowRuntime part itself is correct:

```text
AgentExecutionResult failure
    -> compatibility event name provider.failed
    -> payload retains:
         error_code
         failure_domain
         retryable
         execution_id
```

That satisfies the internal EventBus compatibility contract.

### P0-01 — `chat_router.py` strips the new structured metadata

Current streaming subscriber:

```text
provider.failed
    -> {"error": evt.payload["error"]}
```

drops:

```text
error_code
failure_domain
retryable
execution_id
```

Current non-streaming subscriber converts `provider.failed` to `HTTPException` using only:

```text
status_code
error string
```

and also drops the structured envelope.

Therefore the R2.1 requirement:

```text
preserve failure origin across WorkflowRuntime and
streaming/non-streaming transport surfaces
```

is not met.

### Required v2 fix

Add `chat_router.py` handling that preserves a structured error object for both surfaces while keeping backward compatibility.

Conceptual SSE payload:

```json
{
  "error": "checkpoint serialization failed",
  "error_code": "AGENT_PERSISTENCE_SERIALIZATION_FAILED",
  "failure_domain": "AGENT_PERSISTENCE",
  "retryable": false,
  "execution_id": "..."
}
```

Conceptual non-streaming HTTP detail should retain the structured metadata rather than only a string.

The exact wire shape should be checked against existing API tests before changing it, but v1 cannot be called complete while transport strips the fields.

## 9. Hunk 8 — `se/tests/architecture/test_r2_1_stabilization.py`

### Verdict: BLOCKED AS EXIT-GATE SUITE — implementation test is useful but incomplete

### PASS — real SQLite mappingproxy regression

The test correctly exercises:

```text
AgentRuntime
-> frozen AgentContextSnapshot
-> InferenceRequest with nested immutable metadata
-> DurableAgentStore
-> AgentRepository
-> SQLite JSON
```

This closes the original production test hole.

### P0-02 — failure-domain test does not reproduce real persistence failure

The current test injects:

```text
_FailedAgentRuntime
    -> returns a preconstructed AGENT_PERSISTENCE failure result
```

It proves only that WorkflowRuntime copies fields from an already-classified result.

It does **not** prove the required sequence:

```text
inference succeeds
-> persistence write fails
-> AgentRuntime classifies the failure as AGENT_PERSISTENCE
-> Workflow/transport preserves it
```

### Required v2 test

Use a DurableAgentStore/test persistence seam that succeeds for execution startup and deliberately raises `AgentPersistenceSerializationError` on checkpoint write after fake inference returns successfully.

Assert:

```text
provider inference called successfully
AgentExecutionResult.error_code == AGENT_PERSISTENCE_SERIALIZATION_FAILED
failure_domain == AGENT_PERSISTENCE
durable execution ends FAILED
Workflow/transport retains the same structured fields
```

### P1-05 — revision assertion missing

R2.1 plan requires proof that R2 revision/CAS semantics remain intact. The real SQLite test should assert the final expected revision, not only `state == COMPLETED`.

For the current create/start/finish sequence, verify the expected revision according to actual R2 semantics.

### P1-06 — non-finite float rule lacks regression

Serializer intentionally rejects NaN/Infinity. Add one focused test.

### P1-07 — transport tests missing

Add streaming and non-streaming `chat_router` tests proving the structured error envelope survives the EventBus bridge.
